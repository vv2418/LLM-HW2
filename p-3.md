### Why Use Docker Stack Deploy vs Docker Compose?

| Feature | `docker compose up` | `docker stack deploy` |
|---------|-------------------|---------------------|
| **Orchestration** | Single host | Multi-node cluster |
| **Scaling** | Manual | Declarative with auto-balancing |
| **High Availability** | No automatic recovery | Automatic failover across nodes |
| **Load Balancing** | External required | Built-in ingress load balancer |
| **Rolling Updates** | Container recreation | Zero-downtime updates |
| **Secrets Management** | Environment files | Encrypted secrets API |
| **Service Discovery** | Docker DNS (single host) | Swarm overlay network |

**When to use Stack Deploy:**
- Production multi-node deployments
- High availability requirements
- Automatic service recovery needed
- Horizontal scaling across hosts

**When to use Compose:**
- Development environments
- Single-server deployments
- Testing and prototyping
- When using Compose V2 features not in Swarm

## Deployment

### Known Limitation: Swarm Incompatibility

The Dify `docker-compose.yaml` file uses extended `depends_on` syntax:

```yaml
depends_on:
  db:
    condition: service_healthy
  redis:
    condition: service_healthy
```

**This is NOT supported in Docker Swarm** (Compose v3.x format).

**Error when attempting:**
```bash
$ docker stack deploy -c docker-compose.yaml dify
services.worker.depends_on must be a list
```

**Solution:** Use Docker Compose for deployment (as recommended by official Dify documentation here - https://docs.dify.ai/en/getting-started/install-self-hosted/docker-compose ).

### Deploy with Docker Compose

```bash
# Ensure you're in the docker directory
cd ~/path/to/dify/docker

# Start all services
docker compose up -d
```

## Known Limitations

### Docker Swarm Incompatibility

**Issue:** The upstream Dify `docker-compose.yaml` cannot be deployed with `docker stack deploy`.

**Reason:** Uses extended `depends_on` syntax not supported in Swarm v3.x:

```yaml
# Not supported in Swarm
depends_on:
  db:
    condition: service_healthy
    
# Swarm requires
depends_on:
  - db
```

**Impact:**
- Cannot use `docker stack deploy` for multi-node deployment
- Must use `docker compose up` for single-node deployment

**Workaround Options:**

1. **Use Docker Compose** (current approach)
   - Suitable for dev/test and single-server production
   - Full feature support

2. **Modify compose file** for Swarm compatibility:
   - Convert `depends_on` to simple lists
   - Add `version: "3.8"`
   - Remove `container_name` directives
   - Note: File is auto-generated, changes may be overwritten

3. **Wait for upstream fix** in Dify repository

**This limitation is documented in:**
- `SWARM_SETUP.md` - Detailed Swarm analysis
- Official Dify docs - Recommend Docker Compose deployment

## Troubleshooting

### Cannot Access Web UI

**Symptom:** http://localhost not loading

**Solutions:**

```bash
# 1. Check nginx is running
docker compose ps nginx
# Should show: 0.0.0.0:80->80/tcp

# 2. Check nginx logs
docker compose logs nginx

# 3. Restart nginx
docker compose restart nginx

# 4. Check port 80 isn't occupied
lsof -i :80

# 5. Try alternate port
# Edit docker-compose.yaml:
# ports: "8080:80"
# Then: docker compose up -d nginx
# Access: http://localhost:8080
```

### Database Connection Errors

**Symptom:** API logs show "could not connect to database"

**Solutions:**

```bash
# 1. Check database is healthy
docker compose ps db
# Should show: (healthy)

# 2. Check database logs
docker compose logs db

# 3. Wait for health check
# May take 30-60 seconds after start

# 4. Restart API after database is healthy
docker compose restart api worker worker_beat
```

### Model Provider Configuration Fails

**Symptom:** API key validation fails

**Solutions:**

1. **Verify API key:**
   - Check no extra spaces
   - Ensure key is active
   - Test at provider's playground

2. **Check network connectivity:**
   ```bash
   # Test from inside container
   docker compose exec api curl -I https://api.openai.com
   ```

3. **Check API quota:**
   - OpenAI: Check usage limits
   - May need to add payment method

4. **Try alternative endpoint:**
   - Configure `OPENAI_API_BASE` in UI
   - Use proxy if needed

### Worker Not Processing Jobs

**Symptom:** Workflow executions hang

**Solutions:**

```bash
# 1. Check worker logs
docker compose logs worker

# 2. Check Redis connection
docker compose logs redis

# 3. Restart worker
docker compose restart worker worker_beat

# 4. Check Celery beat is running
docker compose ps worker_beat
```

### Out of Memory

**Symptom:** Containers restarting, system slow

**Solutions:**

1. **Increase Docker resources:**
   - Docker Desktop → Settings → Resources
   - RAM: 8GB minimum
   - CPUs: 4 recommended

2. **Stop unused containers:**
   ```bash
   docker compose stop weaviate  # If not using vector search
   docker compose stop plugin_daemon  # If not using plugins
   ```

3. **Monitor resource usage:**
   ```bash
   docker stats
   ```

### Complete Reset

If all else fails:

```bash
# Stop and remove everything
docker compose down -v

# Remove all Dify images
docker images | grep dify | awk '{print $3}' | xargs docker rmi -f

# Start fresh
docker compose pull
docker compose up -d
```
